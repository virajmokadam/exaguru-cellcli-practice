Quick Guide

How candidates should use this lab

Start at Level 1 and move in order. First read the topic, then run the example commands, then move to the exercise section inside each tab. Use SCENARIO ... commands to switch from normal to warning or failure conditions and repeat the same checks.

Level 1 — Get comfortable with CellCLI navigation Beginner
  • Goal: learn object names and basic listing style.
  • Run: HELP, LIST CELL, LIST CELLDISK, LIST GRIDDISK, LIST PHYSICALDISK
  • Then run: DESCRIBE CELL, DESCRIBE CELLDISK
  • Exercise: identify flash disks vs hard disks and map them to cell / diskgroup usage.
Level 2 — Work with attributes and detail output Core
  • Goal: reduce noise and focus on key attributes.
  • Run: LIST CELL ATTRIBUTES name,status,cellVersion,cellsrvStatus,msStatus,rsStatus
  • Run: LIST CELLDISK ATTRIBUTES name,status,diskType,size,freeSpace,errorCount
  • Run: LIST PHYSICALDISK DETAIL
  • Exercise: note which attributes help for quick health check.
Level 3 — Filtering and targeted checks Intermediate
  • Goal: locate only the object that matters.
  • Run: LIST GRIDDISK WHERE asmDiskGroupName = 'DATA' ATTRIBUTES name,asmDiskGroupName,status,size
  • Run: LIST PHYSICALDISK WHERE status != 'normal' ATTRIBUTES name,slotNumber,diskType,status,errorCount
  • Run: LIST CELLDISK WHERE name LIKE 'FD%' ATTRIBUTES name,status,size,errorCount
  • Exercise: use SCENARIO WARNING and repeat the same commands.
Level 4 — Metrics, alerts, and flash usage Ops
  • Goal: read performance and alert indicators.
  • Run: LIST METRICCURRENT
  • Run: LIST METRICHISTORY WHERE alertState != 'normal' ATTRIBUTES name,metricObjectName,metricValue,alertState,collectionTime
  • Run: LIST ALERTHISTORY, LIST ALERTDEFINITION
  • Run: LIST FLASHCACHE, LIST FLASHCACHECONTENT
  • Exercise: determine whether the issue is capacity related, latency related, or disk related.
Level 5 — Troubleshooting flow for storage incidents Advanced
  • Goal: follow a realistic triage sequence.
  • Step 1: CHECK CELL STATUS
  • Step 2: SHOW ALERTS
  • Step 3: SHOW LOG ALERT
  • Step 4: SHOW LOG CELLSRV and SHOW LOG MS
  • Step 5: RUN DIAG DISKS or RUN DIAG FLASH
  • Step 6: verify impact using LIST GRIDDISK, LIST PHYSICALDISK, LIST METRICCURRENT
Scenario pack — What to practice Exercises

Use the same triage rhythm for every scenario: SHOW SCENARIO → CHECK CELL STATUS → SHOW ALERTS → targeted LIST ... checks → SHOW LOG ... → RUN DIAG ....

  • HEALTHY: establish baseline output for all major objects.
  • Commands: LIST CELL DETAIL, LIST CELLDISK, LIST GRIDDISK, LIST PHYSICALDISK, LIST METRICCURRENT.
  • What to learn: what “normal” looks like before troubleshooting begins.
  • WARNING: soft degradation on disk / celldisk with moderate alerts.
  • Commands: CHECK STORAGE HEALTH, LIST PHYSICALDISK WHERE status != 'normal' ATTRIBUTES name,slotNumber,diskType,status,errorCount, LIST CELLDISK ATTRIBUTES name,status,errorCount,freeSpace, SHOW LOG ALERT.
  • What to learn: identify the first object showing warning and correlate alert text with object status.
  • FAILURE: failed physical disk, inactive griddisk, elevated latency.
  • Commands: SHOW ALERTS, LIST GRIDDISK WHERE status != 'active' ATTRIBUTES name,asmDiskGroupName,status,errorCount, LIST METRICHISTORY WHERE alertState != 'normal' ATTRIBUTES name,metricValue,alertState,collectionTime, SHOW LOG CELLSRV, RUN DIAG DISKS.
  • What to learn: move from symptom to failed component and explain likely next DBA/storage-admin step.
  • CAPACITY: storage pressure, flash cache or cell disk usage high.
  • Commands: LIST FLASHCACHE, LIST FLASHCACHECONTENT, LIST THRESHOLD, LIST ALERTHISTORY, SHOW LOG MS.
  • What to learn: differentiate capacity stress from outright hardware failure.
  • RESYNC: rebalance / recovery / resync style workload in progress.
  • Commands: LIST IORMPLAN, LIST METRICCURRENT, LIST METRICHISTORY, SHOW LOG RS, RUN DIAG SERVICES.
  • What to learn: explain why metrics can look busy even when hardware is not failed.

Suggested exercise path: start with HEALTHY, repeat same command set on WARNING and FAILURE, then finish with CAPACITY and RESYNC to practice interpretation rather than only fault finding.
